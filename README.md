# KVITKA space — сайт Наталії Квітки

Статичний односторінковий сайт-візитка: формати роботи, відгуки, дипломи,
страхова компенсація, умови співпраці. Без бекенду й бази — усі звернення
йдуть у **Telegram** (заготовлений текст під кожен формат) та **WhatsApp**.

Технологій нема — це просто `index.html` + `styles.css` + `app.js`.
Node потрібен лише для команди збірки під Vercel.

---

## Файли

| Файл | Що всередині |
|---|---|
| `index.html` | розмітка, усі екрани, `<head>` із SEO |
| `styles.css` | стилі |
| `app.js` | **весь контент** (формати, ціни, болі, відгуки, список сертифікатів) + навігація |
| `public/kvitka/` | фото форматів, `hero.jpg`, `certs/` — 19 сертифікатів |
| `build.mjs` | збирає `.vercel/output` для Vercel |

---

## Як редагувати контент

Майже все — у **`app.js`**, зверху файлу, у зрозумілих масивах:

- **Контакти** — блок `КОНТАКТИ` на самому початку (`telegramUrl`, `whatsappUrl`,
  `instagramUrl`, `communityUrl`). ⚠️ Ці ж посилання є ще й у `index.html`
  (блок «Контакт» + SEO-теги) — міняй в обох місцях.
- **Формати, ціни, описи** — масив `services`. Поле `message` — це текст, який
  підставляється у Telegram, коли людина тисне «Написати».
- **Болі** («Можливо, ви теж із цим стикались») — `painTopics`.
- **«Що зміниться»** — `changes`.
- **Відгуки** — `reviews` (поле `service` прив'язує відгук до формату:
  `individual` / `group` / `circle` / `game` / `couples`).
- **Підбір формату** — `picker`.

**Тексти екранів «Умови співпраці» та «Страхова компенсація»** — прямо в `index.html`.

**Сертифікати:** поклади нові файли в `public/kvitka/certs/` і додай імена в
масив `certManifest` в `app.js`.

**Фото форматів:** заміни файли в `public/kvitka/` (ті самі імена) — і **підніми
число `?v=1` → `?v=2`** скрізь у `app.js` та `index.html` (інакше браузери
показуватимуть старе фото з кешу). Простий пошук-заміна по обох файлах.

## Локальний перегляд

```bash
python3 -m http.server 4173
```

Відкрити <http://127.0.0.1:4173>. На телефоні (той самий Wi-Fi) —
`http://<IP-комп'ютера>:4173`.

## Деплой

Це просто статичні файли — підійде будь-який хостинг (Vercel, Netlify,
Cloudflare Pages, GitHub Pages, звичайний хостинг тощо).

**Найпростіше — залити папку як є** (index.html у корені). `build.mjs` потрібен
лише для платформ, які працюють через Vercel Build Output API:

- **Netlify / Cloudflare Pages / GitHub Pages:** заливаєш папку, корінь = ця тека.
  Build command не потрібен.
- **Vercel:** Framework Preset — *Other*, Build Command — `npm run build`,
  Output Directory — залишити порожнім (використовується `.vercel/output`).

Один нюанс: усі внутрішні «сторінки» — це один `index.html` (SPA-навігація на
JS). Якщо хостинг вимагає fallback на 404 — вкажи `index.html`.

## ⚠️ Що зробити після деплою

1. **Домен у SEO-тегах.** У `index.html` (`<head>`) стоїть заглушка
   `YOUR-DOMAIN.com` у 5+ місцях (canonical, og:url, og:image, twitter:image,
   JSON-LD). Заміни на реальний домен — один пошук-заміна по файлу.
   Поки не заміниш — просто не працюватиме прев'ю при шерінгу, на сам сайт не впливає.
2. **Індексація Google.** Якщо хостинг має «захист паролем / preview protection» —
   вимкни його для production, інакше пошуковики не побачать сайт.
3. **Instagram / Telegram.** Перевір, що `kvitka__nata` і `Kvitka7778` — актуальні
   акаунти (у `app.js` зверху + у `index.html`). Канал `KVITKA Space` варто
   зробити публічним (@username).
4. **Умови співпраці.** Текст у `index.html` — робочий, але не юридичний документ.
